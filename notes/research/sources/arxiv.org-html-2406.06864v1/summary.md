## What the source claims

Proposes **metamorphic prompt testing**: validate LLM-generated code without ground-truth
oracles by paraphrasing the prompt, generating multiple programs, and cross-validating their
outputs for inconsistency. Central claim: it detects 75% of erroneous GPT-4 programs on
HumanEval at an 8.6% false positive rate, and used as a post-processor it raises accuracy
from 85.4% to 89.0%.

Verbatim quotes:

> "Our evaluation on HumanEval shows that metamorphic prompt testing is able to detect 75% of
> the erroneous programs generated by GPT-4, with a false positive rate of 8.6%."

> "we leverage just one simple metamorphic relation: Taking prompts with the same meaning,
> the LLM should generate programs with the same semantics."

> "among 164 code generation prompts in HumanEval, our approach is able to averagely detect
> 75% (potentially 83% with a more conservative configuration) out of all 24 erroneous
> programs generated by GPT-4, with a false positive rate of 8.6%."

> "a developer need to look at only 30 LLM-generated programs to find 18 of them as truly
> erroneous (with 12 false positives), while missing only 6 erroneous programs."

> "If adopting our approach as a post-processor of GPT-4 by rejecting the generated programs
> identified as erroneous, it is able to boost the accuracy from 85.4% to 89.0%."

> "the generated test cases can detect only run-time errors such as dead loops and crashes
> instead of assertion errors ... our evaluation of GPT-4 ... shows that run-time errors are
> rarely triggered by LLM-generated code and all errors we observed are assertion errors."

On the cross-validation rule:

> "we report an error only if the majority of the paraphrase programs have different
> semantics from the target program."

## Method / evidence type

- Technique with four steps: paraphrase the prompt's natural-language description (prepend
  "Can you paraphrase the following paragraph?"); generate target + paraphrase programs
  ("Can you generate python code for the following function?"); generate test inputs on the
  target program with a fuzzer; cross-validate outputs.
- Paraphrasing alters only the description part; signature and worked examples left
  unchanged.
- Test-input generation: **python-AFL** (coverage-guided fuzzing), "limit the number of our
  generated test inputs to 20."
- Cross-validation: report error if `len(DiffSet) > len(Paraprogs)/2` (Algorithm 1).
- LLM: "gpt-4-1106-preview model provided by OpenAI." Benchmark: HumanEval (164
  prompt/canonical-solution pairs); canonical solutions/tests used "only for evaluation."
- Research questions: RQ1 effectiveness; RQ2 ablation (no-paraphrase variant; conservative
  cross-validation variant); RQ3 qualitative analysis of false positives/negatives.
- Metrics defined: Accuracy, Recall, Precision (defined in paper as FP/(FP+TP)), False
  Positive Rate = FP/(FP+TN). (Note: the paper's FP definition text reads "reported ... as
  erroneous is considered as a true positive" — an apparent typo in the source.)

## Scope, limitations, and gaps (stated by the authors)

- External validity: "we evaluated our approach on only GPT-4 and HumanEval, which consists
  of 164 prompts for python code generation. It is possible that our evaluation results may
  not apply to other LLMs, datasets, and programming languages."
- Internal validity threat: "potential bugs and errors in our implementation."
- Effectiveness hinges on paraphrase diversity: false negatives arise from "high similarity
  among paraphrases"; false positives arise from "the paraphrase clustering effect" (all
  paraphrases similar to each other, so a shared error forms a false majority).
- Only 24 erroneous programs in the evaluation set — small denominator for recall estimates.
- Future work: more LLMs/benchmarks/languages, measuring paraphrase similarity, additional
  metamorphic relations (e.g., negation), using the signal as feedback/fine-tuning.
