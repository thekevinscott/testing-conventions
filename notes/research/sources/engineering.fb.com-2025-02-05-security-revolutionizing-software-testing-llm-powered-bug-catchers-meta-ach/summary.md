## What the source claims

The post announces **Automated Compliance Hardening (ACH)**, described as "a system for
mutation-guided, LLM-based test generation." The central claim is that ACH targets *specific
faults* rather than uncovered code, and generates tests it can *prove* will catch those faults.

Verbatim quotes:

> "ACH hardens platforms against regressions by generating undetected faults (mutants) in source
> code that are specific to a given area of concern and using those same mutants to generate
> tests."

> "ACH automatically generates unit tests that target a particular kind of fault. We describe
> the faults we care about to ACH in plain text. The description can be incomplete, and even
> self-contradictory, yet ACH still generates tests that it proves will catch bugs of the kind
> described."

> "Traditionally, automated test generation techniques sought merely to increase code coverage.
> As every tester knows, this is only part of the solution because increasing coverage doesn't
> necessarily find faults."

> "ACH is a radical departure from this tradition, because it targets specific faults, rather
> than uncovered code, although it often also increases coverage in the process of targeting
> faults."

The three-step workflow, quoted:

> "1. An engineer describes the kind of bugs they're concerned about.
> 2. ACH uses that description to automatically generate lots of bugs.
> 3. ACH uses the generated bugs to automatically generate lots of tests that catch them."

Claim of novelty:

> "LLM-based test generation and LLM-based mutant generation are not new, but this is the first
> time they've been combined and deployed in large-scaled industrial systems."

On rule-based mutation testing's shortcomings (the prior art ACH replaces):

> "In earlier approaches, mutants themselves would be automatically generated (most often using a
> rule-based approach). But this method would result in mutants that weren't particularly
> realistic in terms of how much of a concern they actually represent."

> "even with the mutants being automatically generated, humans would still have to manually write
> the tests that would kill the mutants (catch the faults)."

ACH is said to be "founded on the principles of Assured LLM-based Software Engineering," which
"keeps verifiable assurances that its tests do catch the kind of faults described."

## Scope, limitations, and gaps

- **Self-reported, promotional source.** Claims of usefulness ("engineers found ACH useful")
  are Meta's own characterization with no methodology, sample size, or comparison group shown.
- The strong assertion that ACH generates tests "it proves will catch bugs" / with "guarantee"
  is stated without the underlying formalism; the proof/assurance mechanism is attributed to the
  external "Assured LLM-based Software Engineering" work, not demonstrated here.
- Applied to **privacy testing** as the primary worked domain ("ACH can be applied to any class
  of faults"), but the post gives no domain-by-domain evidence.
- Platforms named (Facebook Feed, Instagram, Messenger, WhatsApp) but no per-platform data.
- "WHAT'S NEXT" lists open problems Meta itself flags: "developing methods to measure mutant
  relevance, and detecting existing faults" — i.e., mutant relevance is not yet measured.
- Full scientific substantiation lives in the arXiv paper (2501.12862), **not captured.**
